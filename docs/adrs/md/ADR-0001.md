## Context

El proyecto necesita una interfaz web moderna y fácil de usar tanto para alumnos como para profesores. Uno de los requisitos principales es poder renderizar fórmulas matemáticas complejas en tiempo real (LaTeX). Además, se ha solicitado que la aplicación sea "dockerizable", por lo que conviene usar una tecnología que permita generar archivos estáticos que sean fáciles de empaquetar y servir. He decidido basarme en React y TypeScript porque ya tengo experiencia previa con ellos, lo que me permitirá avanzar de forma más segura y centrarme en la lógica del Trabajo de Fin de Grado.

### Alternatives considered

- Create React App (CRA): Es la herramienta clásica para empezar proyectos en React, pero actualmente está desactualizada, es lenta al compilar y la propia documentación oficial de React ya no la recomienda.
- Next.js: Es una herramienta muy potente que ofrece SSR (Server-Side Rendering, es decir, que las páginas web se calculan y generan en el servidor antes de enviarse al navegador del usuario, en lugar de cargarse directamente en su ordenador). Aunque es muy popular, para este proyecto añadiría una complejidad innecesaria, ya que obligaría a tener un servidor Node.js ejecutándose continuamente en producción.
- Vue/Angular: Son alternativas totalmente válidas para el frontend, pero al no tener experiencia previa con ellas, la curva de aprendizaje retrasaría considerablemente el desarrollo inicial.

## Decision

Se utilizará React junto con TypeScript, apoyado en Vite como herramienta de construcción (build tool). Vite se encargará de compilar el código del frontend y generar una carpeta con archivos estáticos (HTML, CSS y JavaScript puros). Estos archivos se servirán de forma muy sencilla utilizando un servidor web dentro de un contenedor de Docker.

## Consequences

Pros:

- Arranque y recarga en caliente rápido.
- Build a estáticos sencillo de desplegar y dockerizar.
- Ecosistema completo con librerías compatibles con LaTeX.

Contras / riesgos:

- Al ser una tecnología que da mucha libertad, requiere que yo mismo mantenga una buena disciplina para tener el código limpio y ordenado, evitando que se vuelva caótico a medida que el proyecto crezca.

## Compliance

- Uso de comandos estándar para el desarrollo: dev (programar), build (compilar) y preview (probar lo compilado).
- Creación de un Dockerfile en dos fases (multi-stage): una primera fase para compilar el código fuente utilizando Node.js, y una segunda fase que utilice un servidor web ligero y genérico para servir los archivos estáticos resultantes.
- ESLint/Prettier y pruebas unitarias mínimas en el front.
