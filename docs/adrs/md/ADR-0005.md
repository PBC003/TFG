## Context
Uno de los requisitos impuestos para este Trabajo de Fin de Grado es que la aplicación completa debe poder empaquetarse y ejecutarse utilizando Docker. El objetivo principal es garantizar un entorno de ejecución totalmente reproducible que incluya el frontend, el backend y sus respectivas bases de datos.

### Alternatives considered
- Ejecución local sin contenedores: incumple el requisito y dificulta reproducibilidad.
- Docker solo para producción: reduce valor en desarrollo y dificulta que otros colaboradores o evaluadores puedan configurar el proyecto fácilmente para revisarlo.
- Compose con servicios separados: Es el estándar ya que permite definir y aislar cada parte de la aplicación (frontend, backend y bases de datos) en contenedores independientes que se comunican entre sí de forma segura, garantizando la reproducibilidad y facilitando las pruebas.

## Decision
Se utilizará la herramienta Docker Compose, creando un archivo docker-compose.yml que definirá la infraestructura del sistema dividida en cuatro servicios principales: el frontend (React), el backend (NestJS), la base de datos relacional (MariaDB) y la base de datos documental (MongoDB).

Para el frontend, se aplicará una técnica de compilación en múltiples etapas (multi-stage build), donde el código se compilará primero y luego se servirá como estático. El backend expondrá la API y se conectará a las BDs mediante variables de entorno.

## Consequences
Pros:
- Garantiza la reproducibilidad total del entorno, sin importar el sistema operativo.
- Facilita enormemente la revisión, evaluación y despliegue del proyecto.
- Simplifica la configuración inicial del entorno de trabajo.


Contras / riesgos:
- Añade un tiempo extra de configuración e investigación al inicio del desarrollo.
- Requiere rigurosidad con la configuración (redes internas, las variables de entorno, …).

## Compliance
- Se redactará un archivo README.md claro que detalle las instrucciones para levantar el sistema mediante el comando docker compose up, especificando los puertos utilizados.
- Se configurarán volúmenes persistentes en Docker para MariaDB y MongoDB, asegurando que los datos (usuarios, preguntas, intentos) no se pierdan al apagar los contenedores.
- Se implementarán pruebas automáticas de estado (healthchecks) en la configuración de Docker Compose para asegurar que el backend no intente arrancar hasta que las bases de datos estén completamente inicializadas y listas para recibir conexiones.
