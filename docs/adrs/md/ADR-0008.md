# ADR-0008 - Adopción de MUI como librería base de interfaz

**Proyecto:** TFG – Plataforma de cuestionarios para Cálculo  
**Fecha:** 2026-03-19  
**Estado:** Accepted

## Estado
☐ Proposed  
☒ Accepted  
☐ Superseded

## Contexto
En busca de una consistencia visual y velocidad de construcción se necesita una base común para formularios, navegación, responsive y estilos sin perder capacidad de personalización.

## Alternativas consideradas
- Construir todos los componentes base desde cero con CSS propio. Aporta control total, pero penaliza tiempo, mantenimiento y consistencia.
- Usar utilidades de estilos y componentes ad hoc sin una librería consolidada. Puede funcionar en pequeño, pero escala peor y exige más disciplina manual.
- Adoptar una librería madura de componentes React con soporte de accesibilidad, theming y ecosistema estable. Reduce fricción y acelera el trabajo de UI.

## Decisión
Se adopta Material UI (MUI) como librería base de componentes del frontend.

La decisión implica que MUI se utilizará como base para layout, formularios, navegación, feedback visual y componentes reutilizables.

La adopción no implica aceptar sin criterio el aspecto por defecto; se personalizará mediante `theme`, tokens y composición propia.

Las nuevas pantallas visibles del producto deben apoyarse preferentemente en la misma base de componentes para mantener coherencia.

## Consecuencias
**Pros:**
- Acelera el desarrollo de interfaces estables y reutilizables.
- Aporta componentes accesibles y ampliamente probados.
- Facilita una identidad visual homogénea mediante `theme` y patrones comunes.

**Contras / riesgos:**
- Introduce dependencia de una API y convenciones propias que habrá que mantener con criterio.
- Puede producir una apariencia demasiado genérica si no se personaliza adecuadamente.

## Cumplimiento
La documentación técnica deberá tratar MUI como estándar de interfaz del proyecto mientras no exista una decisión posterior que lo sustituya.
